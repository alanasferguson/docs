## Overview

Dedalus Machines run on a base Ubuntu (lynx, x86_64) image by default. Custom Images lets you upload, register, and launch your own OS images on Dedalus Machines. Bring any compatible disk image and run it fast.

Dedalus Custom Images give you full control over the operating system and software stack running on your Dedalus Machine. Upload a custom disk image, whether it is a hardened Linux distribution, a pre-configured appliance, or a specialized workload environment, and launch machines from it just like any standard image.

## Why Custom Images

The base Ubuntu image works for many workloads but does not include system-level dependencies that many agents require. Custom Images solves this by letting you bring your own environment. Common use cases include:

- Agents that require specific Python versions, ML frameworks like PyTorch or CUDA, or lower-level libraries like ffmpeg
- Pre-configured appliances with all dependencies baked in, eliminating setup scripts at machine creation time
- Specialized workload environments that need consistent, reproducible runtime conditions across every machine

## How It Works

Build or pull a Docker image locally with your required dependencies and push it to ECR, GHCR, or Docker Hub. Then create a machine specifying your custom image URI.

Dedalus pulls the image, caches it internally, and boots the machine into your environment. On subsequent machine creation using the same image, Dedalus pulls from its internal cache rather than the external registry, reducing boot time.

## Supported Registries

- Amazon ECR
- GitHub Container Registry (GHCR)
- Docker Hub

## Image Requirements

- Images must be OCI-compatible
- Kernel-level customization is not supported in this release
- Authentication via short-lived credentials or OAuth tokens through DAuth

## Key Concepts

<CardGroup cols={2}>
  <Card title="OCI-Compatible Images" icon="box">
    Dedalus supports any image that conforms to the Open Container Initiative spec. Build with Docker or any OCI-compliant tool and push to your registry of choice.
  </Card>
  <Card title="Internal Image Cache" icon="database">
    Dedalus caches your image after the first pull. Subsequent machine creation uses the cached version, keeping boot times fast and removing dependency on external registry availability.
  </Card>
  <Card title="Registry Authentication" icon="lock">
    Connect ECR, GHCR, or Docker Hub using short-lived credentials or OAuth tokens. Dedalus handles credential isolation through DAuth so long-lived secrets are never stored.
  </Card>
  <Card title="Persistent Runtime" icon="server">
    Machines boot into your custom environment and persist filesystem and memory across sessions. You only pay for active compute, not idle time.
  </Card>
</CardGroup>
